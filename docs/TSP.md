# MAPPING TSP TO GROVER ORACLES

To solve the Traveling Salesperson Problem using Grover's Algorithm, we must construct an Oracle that encodes the specific constraints of the graph. For a 4-city problem, we first define a distance matrix representing the cost of travel between any two nodes. We then represent the possible paths as quantum states. Since we must visit each city exactly once and return to the start, we are searching for the Hamiltonian Cycle with the minimum total weight. The Oracle is built as a combination of Arithmetic Circuits and Comparison Logic. First, the Oracle uses adders to sum the weights of the edges corresponding to the path encoded in the qubit register. Second, it uses a comparator circuit to check if this sum is less than a threshold value 'k'. If both the path is a valid permutation and the cost is less than 'k', the Oracle applies a phase flip to that state. Because Grover's is a search algorithm and not a direct optimizer, we often use it in a hybrid loop: we pick a threshold, run Grover's to find a path, then lower the threshold and run it again until no more solutions are found. This process effectively finds the global minimum. For your Quantum Machine Learning goals, this Oracle construction is a precursor to understanding how we encode classical cost functions into quantum operators.
